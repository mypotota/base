# H16 风扇控制前景提要

H16 教程把控制分成三步。客户端通过 Binder 请求 Android 系统服务，系统服务通过本地 socket 把命令交给 C++ 守护进程，守护进程经 Linux 内核的 GPIO 或 PWM 驱动控制引脚。

```text
设置页或其他有权限的客户端
  │ Binder（AIDL 方法调用）
  ▼
system_server 中的 H16FanService，服务名 h16_fan
  │ Unix 域流式 socket（/dev/socket/h16_fand）
  ▼
C++ 守护进程 h16_fand
  │ 读写 /sys 下的 sysfs 属性
  ▼
Linux GPIO 或 PWM 驱动 → SoC 控制器 → GPIO174 对应的引脚 → 板上风扇电路
```

## Binder 和 C++ 监听的 socket 有什么关系？

Binder 和 Unix 域 socket 是两种独立的进程间通信机制，都由内核提供支持。Binder 传递的是一次远程方法调用。AIDL 生成的客户端代理把方法编号和参数写入 Parcel，Binder 驱动把事务交给服务端，服务端 Stub 调用实际方法，再把结果送回客户端。Unix 域流式 socket 在同一台设备的两个进程之间传输字节，字节的含义由双方约定。[AOSP Binder IPC 文档](https://source.android.com/docs/core/architecture/hidl/binder-ipc?hl=en)

以基础版的短时打开为例，完整过程如下。

1. 客户端调用 `setMode(1)`。请求通过 Binder 到达 `system_server` 里的 `H16FanService`，服务检查调用者的控制权限。
2. Java 服务通过 `LocalSocket` 连接 `/dev/socket/h16_fand`，按教程约定发送一个 ASCII 字符 `1`。同一套协议还用 `?` 查询、`A` 切回自动、`0` 请求短时关闭。
3. Android 的 `init` 创建 socket 并把文件描述符交给 C++ 进程。C++ 调用 `listen()` 开始监听，通过 `poll()` 等待连接，通过 `accept4()` 接收连接，核对对端 UID 后用 `recv()` 读取命令。在没有连接的等待周期里，进程也会继续更新温控状态。
4. C++ 根据命令和温控状态决定是否改变 GPIO 输出，然后把状态作为一行文本写回 socket。Java 读回并解析成整数数组，再通过 Binder 把结果返回给客户端。基础版的第一列是 GPIO 回读值，实际风扇有没有转需要观察或测量。[风扇控制系统服务实作教程](风扇控制系统服务实作教程.md)

## 硬件操作在哪里进入内核？

C++ 守护进程运行在用户空间。它对 `/sys/class/gpio/gpio174/value` 调用 `write()` 时，系统调用进入内核。这里的 sysfs 节点由内核提供，写入会调用对应的内核处理逻辑，由 GPIO 驱动配置 SoC 控制器，最终改变引脚电平。PWM 版同样经过内核，写入的是 PWM 通道的 `period`、`duty_cycle` 和 `enable`。[Linux PWM sysfs 接口](https://kernel.org/doc/html/v6.5/driver-api/pwm.html)

可以把温控策略和硬件操作理解为两个问题。**什么时候转、转多久、用户能不能手动关闭**，由系统服务和守护进程处理。**怎样让芯片引脚改变电平或输出波形**，由内核驱动和 SoC 控制器处理。H16 已经有可用的 GPIO 和 PWM 内核驱动，教程可以复用它们，把温度阈值和手动超时留在用户空间。PWM 版仍需要设备树的引脚复用配置，让 PWM1 的输出接到这根引脚。[风扇 PWM 调速与系统设置进阶课程](风扇PWM调速与系统设置进阶课程.md)

## PWM 是让 IO 按一定频率输出高低电平吗？

是。以正常极性为例，每个周期先输出高电平，再输出低电平，然后重复。频率决定一秒重复多少次，占空比决定每个周期内高电平占多久。反相极性下，有效电平对应低电平。

- 周期为 `T`，频率为 `1 / T`。
- 占空比为 `有效时间 / T × 100%`。Linux sysfs 的 `duty_cycle` 用纳秒表示有效时间。
- H16 实测周期约为 **7.88 ms**，频率约为 **127 Hz**。正常极性下，50% 档每周期约高 **3.94 ms**、低 **3.94 ms**。100% 档的有效时间覆盖整个周期。

这和 ESP32 把引脚接给 LEDC 输出 PWM 的思路相同。H16 把 GPIO174 对应的引脚复用给 PWM1 后，C++ 只在需要时提交参数，SoC 的 PWM 控制器随后持续产生波形。风扇响应取决于风扇和板上电路，50% 占空比不能直接换算成一半转速。H16 实测确认了从 100% 降到 50% 后风力减弱，50% 冷启动和具体 RPM 仍待测量。[H16 风扇实机验证](风扇实测与自动温控修复.md) · [Linux PWM 文档](https://kernel.org/doc/html/v6.5/driver-api/pwm.html)
