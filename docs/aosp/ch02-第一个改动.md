> 完成于 2026-11-15 · 成果：Settings 主页"显示"→"显示 · 我改的"，截图见 `resources/aosp-ch02-settings-modified.png`

## 0. 最终生效的完整流程（抄作业版）

```bash
# ① 改资源（改之前先查布局引用的 key！）
#    packages/apps/Settings/res/values-zh-rCN/strings.xml  → display_settings："显示"→"显示 · 我改的"
#    packages/apps/Settings/res/values/strings.xml         → display_settings："Display"→"Display · My Edit"

# ② 单模块增量编译
source ~/aosp/env_aosp.sh
m Settings

# ③ 部署（前提：模拟器带 -writable-system 启动过）
adb -e remount
adb -e sync system

# ④ 重启 Settings 验证
adb -e shell am force-stop com.android.settings
adb -e shell am start -a android.settings.SETTINGS
```

## 1. 踩坑记录（按出现顺序）

### 坑 1：Settings 的位置想当然
- ❌ `frameworks/base/packages/Settings/`（不存在）
- ✅ `packages/apps/Settings/`
- **仓库地图**：`packages/apps/` = 系统自带 app（Settings/Camera/Dialer...）；`frameworks/base/packages/` = 系统组件（SystemUI/SettingsProvider/**services**=AMS 所在）

### 坑 2：改错了字符串 key
- 改了 `display_settings_title`，主页纹丝不动
- 真相：主页条目引用的是 `@string/display_settings`（见 `res/xml/top_level_settings.xml` 第 60 行）；`display_settings_title` 是 DisplaySettings 二级页的 heading，两个 key 各管各的
- **黄金法则：改 UI 文字前，先打开布局/preference xml 看它实际引用哪个 `@string/xxx`**

### 坑 3：remount failed（本章最大的坑）
- 模拟器默认把 system 分区挂载为**只读**
- 解法：杀掉模拟器，加 `-writable-system` 重启，之后 `adb remount` → `remount succeeded`
- 以后启动命令永远带上它（已更新进 ch00 笔记和 README 速查）

### 坑 4：adb sync 报 `product directory not specified`
- `adb sync` 依赖 `$ANDROID_PRODUCT_OUT`，新 shell 里没 lunch 就没有
- 解法：先 `source ~/aosp/env_aosp.sh`，或手动 `export ANDROID_PRODUCT_OUT=~/aosp/out/target/product/generic_x86_64`

## 3. 附带学到的技能

- **切换模拟器系统语言**：`adb shell setprop persist.sys.locale zh-CN; setprop persist.sys.country CN` + `stop/start`（persist 属性存 /data，重启模拟器也不丢）
- **资源限定符机制实战**：同一 key 在 `values/`（默认英文）和 `values-zh-rCN/`（中文）各有一份，系统按 locale 现取
- **程序化验证界面**（别只靠肉眼看）：
  ```bash
  adb shell uiautomator dump /sdcard/ui.xml   # 抓界面 XML
  adb shell 'grep -o "目标文字" /sdcard/ui.xml'
  adb shell screencap -p /sdcard/s.png        # 截图存证
  ```
  注意设备端 grep 带空格的中文串要整体套一层单引号，否则被设备 shell 拆散
