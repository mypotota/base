# ch03 · 日志实验：看见 AMS/ATMS 跳动（实操笔记）

> 完成于 2026-11-15 · 成果：自己的 Slog 探针跑进了 system_server，真实点击时打印跨进程调用现场
> 本章是一场完整的"假设 → 实验 → 证伪 → 破案"侦探剧，过程比结果值钱

## 0. 最终跑通的完整流程

```bash
# ① 加探针（位置见下方"破案结论"）
#    frameworks/base/services/core/java/com/android/server/wm/ActivityTaskManagerService.java
#    startActivity() 开头：
#    Slog.d("MYTAG", "ATMS.startActivity: callingPackage=" + callingPackage
#            + " from uid=" + Binder.getCallingUid() + " pid=" + Binder.getCallingPid()
#            + " intent=" + intent);

# ② 编译（AMS/ATMS 都属于 services 模块）
source ~/aosp/env_aosp.sh && m services        # 实测 1 分 56 秒

# ③ 部署 + 刷新（不重启模拟器）
adb -e remount
adb -e sync system                              # 推 services.jar + odex/vdex 共 5 个文件
adb -e shell stop && adb -e shell start         # system_server 重新加载新 services.jar

# ④ 触发 + 观察（必须真实点击，见坑 2）
adb -e logcat -c
adb -e shell input tap <x> <y>                  # 真实点击（坐标可用 uiautomator dump 拿）
adb -e logcat -d -s MYTAG
```

## 1. 侦探过程（三个假设两次证伪）

| # | 假设 | 实验 | 结果 |
|---|---|---|---|
| 1 | 流量走 `AMS.startActivity` | 加探针 → `am start` → logcat 空 | ❌ 证伪 |
| 2 | 流量走 `ATMS.startActivity`，am 能触发 | AMS 保留 + ATMS 加探针 → `am start` → 空 | ❌ 证伪 |
| 3 | `am start` 绕道，app 真实点击才走 `startActivity` | `input tap` 真实点击 Settings 条目 | ✅ 命中！ |

破案证据：
- `ActivityManagerShellCommand.java:518`：`am start` 直调 `mInternal.startActivityAsUser(null, null, ...)`，天然绕过 `startActivity`
- app 侧（Instrumentation → `ActivityTaskManager.getService()`）才走 `ATMS.startActivity`

## 2. 命中日志解剖（每字段都是知识点）

```
22:03:53.414  5575  6330 D MYTAG: ATMS.startActivity:
              callingPackage=com.android.settings from uid=1000 pid=5870
              intent={ act=MAIN cmp=com.android.settings/.SubSettings }
```
- `5575` = system_server 进程（探针代码在系统心脏里执行）
- `6330` = Binder 线程（接这通跨进程电话的接线员，见 ch05）
- `pid=5870` = 打电话的人（Settings app 进程）——**Binder.getCallingPid() 与本进程 pid 不同 = 跨进程调用的铁证**
- `uid=1000` = Settings 声明了 `sharedUserId="android.uid.system"`

## 3. 核心知识点

1. **Android 10 大重构：AMS/ATMS 分家**。Activity 启动主链路已迁到 `ActivityTaskManagerService`（wm 包）；`AMS.startActivity` 只剩转发兼容壳。基于 Android 8/9 的老资料在此处会失灵——**读资料必须带版本意识**
2. **`am start` ≠ app 真实启动**：验证 UI/启动行为要用 `input tap`/`uiautomator` 模拟真实操作
3. **排查"日志不出现"三板斧**：对照系统现有日志（确认日志系统正常）→ 查 `getprop | grep log.tag`（级别限制）→ md5 对比两端 jar/odex（部署链完整性）
4. **framework 部署链**：`m services` → `adb sync system`（jar+odex+vdex 一起推）→ `stop/start`（system_server 由新 zygote 重新拉起加载新 dex）

## 4. 遗留状态

- 探针仍在 ATMS.startActivity 里（tag=MYTAG），AMS 里的旧探针保留——它至今沉默，本身就是"流量全走 ATMS"的活教材
- 想还原：删掉两处 Slog.d 再 `m services` + sync + stop/start 即可
