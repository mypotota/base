# ch04 · 调用栈：让代码自己交代（实操笔记）

> 完成于 2026-11-16 · 成果：拿到 ATMS.startActivity 的完整 Binder 调用栈
> 本章经历一次大型武器切换：jdb 断点 →（环境不可用）→ **日志栈**（framework 工程师的真实主力武器）

## 0. 本章主武器：日志版断点（背下来，天天用）

```java
Slog.d("MYTAG", "stack: " + android.util.Log.getStackTraceString(new Throwable()));
```

在任意代码点插入，logcat 就会打印**从此处往上到线程入口的完整调用栈**。不依赖调试器、不冻结系统、system_server/生产环境通吃。**AOSP 工程师 90% 的"调用栈需求"用这行解决。**

完整流程（在 ch03 流程上加一步而已）：
```bash
m services && adb -s emulator-5554 sync system
adb -s emulator-5554 shell stop && adb -s emulator-5554 shell start
adb -s emulator-5554 logcat -c
# 真实点击触发
adb -s emulator-5554 logcat -d -s MYTAG
```

## 1. 战果：Binder 调用三段式（实测栈）

```
at ...ActivityTaskManagerService.startActivity(ActivityTaskManagerService.java:1012)  ← 真身方法（探针行）
at android.app.IActivityTaskManager$Stub.onTransact(IActivityTaskManager.java:1486)   ← AIDL Stub（服务端拆包）
at android.os.Binder.execTransactInternal(Binder.java:1021)                           ← Binder Java 入口
at android.os.Binder.execTransact(Binder.java:994)                                    ← 再往下就是 native/kernel
```

记忆锚点：**Proxy 在 app 进程打包 → Binder 驱动跨进程 → Stub 在 system_server 拆包 → 真身执行**。
自己写过的 AIDL `IXxx.Stub` / `IXxx.Stub.Proxy` 就是同款机制——framework 没有黑魔法。

## 2. jdb/调试器排查全记录（本环境的遗留课题）

尝试链路：`adb forward tcp:PORT jdwp:<pid>` → `jdb -attach localhost:PORT`。

| 步骤 | 现象 |
|---|---|
| `adb jdwp` | 挂起无输出 |
| jdb attach system_server | 握手无应答（TCP 通、JDWP 哑） |
| 重启主机 adb server（`adb kill-server`） | 修复了 shell 卡死，jdwp 仍不通 |
| 重启设备 adbd（unroot/root 切换） | 仍不通 |
| 杀掉 app 重新 fork 再连 | 仍不通（证伪"VM 注册在旧 adbd socket"理论） |
| `/proc/net/unix` | `@jdwp-control` 监听在、一堆 VM 连接在，但全不应答 |

**结论：本环境（AOSP 10 eng 模拟器）adbd 的 jdwp 代理服务系统性不可用，根因未明**。已验证的收益：adbd/adb server 的病态会连累普通 shell 命令，`adb kill-server` 是第一急救药。
**遗留课题**（将来可选）：adbd 源码就在我们手里（`system/core/adb/`），jdwp_service.cc 可以直接读+加日志排查——这本身就是一次绝佳的 AOSP 实战。

## 3. 排查中顺手学的招

- **JDWP 握手探针**（判断调试链路死活，带超时不卡死）：
  ```bash
  python3 -c "
  import socket
  s = socket.create_connection(('localhost', PORT), timeout=5)
  s.settimeout(5); s.sendall(b'JDWP-Handshake')
  print(s.recv(14))"
  ```
- **jdb 本身**：`prebuilts/jdk/jdk9/linux-x86/bin/jdb`（AOSP 自带）；Ubuntu 的 openjdk-17-headless 没有 jdb
- 多模拟器时 `-e` 失效（`more than one emulator`），必须 `adb -s emulator-5554` 精确指定
- `adb kill-server` 大法：任何 adb 灵异现象先来一发

## 4. Android Studio 断点版（标准步骤，其他环境可用）

1. AS 打开任意 app 工程，`Run → View Breakpoints → + → Java Method Breakpoint`
2. 类 `android.app.Instrumentation`，方法 `execStartActivity`（app 进程侧的 framework 出口，调试自己的 app 即可命中，安全）
3. 勇者版：`Attach Debugger to Android Process` 勾选 show all processes → 选 `system_process`（断点会冻结全系统，看完秒 Resume，Watchdog 60 秒会咬人）
4. 命中后调用栈面板 = 免费的 framework 地图

## 6. 作业（5 分钟）

然后 `adb shell cat /data/anr/traces.txt* | head -80`——观察 Settings **空闲时**主线程的栈（Looper.loop 死循环等消息），与本章"点击瞬间"的栈对照。这是理解 Handler 机制的第一手资料（ch06 预习）。
