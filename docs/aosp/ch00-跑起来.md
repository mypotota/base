# ch00 · 跑起来：模拟器与开发闭环（实操笔记）

> 完成于 2026-11-15 · 环境：AOSP 10（aosp_x86_64-eng）· 机器上同时连有一台真机

## 实测要点（踩坑/意外收获）

1. **emulator 不在 PATH 里**：`envsetup.sh` + `lunch` 之后 `emulator` 命令仍找不到，AOSP 源码树自带的模拟器在：
   ```
   ~/aosp/prebuilts/android-emulator/linux_x86_64/emulator
   ```
   启动前手动 export PATH，或直接用绝对路径。

2. **启动命令**（干净启动 + 软件渲染，最稳组合）：
   ```bash
   source ~/aosp/env_aosp.sh
   export PATH=$HOME/aosp/prebuilts/android-emulator/linux_x86_64:$PATH
   emulator -no-snapshot -gpu swiftshader_indirect
   ```
   `lunch` 设置的 `ANDROID_PRODUCT_OUT` 会把模拟器指向 `out/` 里自己编译的镜像，无需额外参数。

3. **eng 版 adbd 默认就是 root**：`adb root` 直接提示 `already running as root`，不需要额外操作。这就是选 `-eng` 变体的核心福利。

4. **同连真机时永远用 `adb -e`**：本机有真机 `ZY22DWKK2P` 长期连着，所有命令加 `-e`（emulator only）防止误操作真机。用 `adb devices` 随时确认。

5. **验证自编镜像的方法**：
   ```
   adb -e shell getprop ro.build.fingerprint
   # Android/aosp_x86_64/generic_x86_64:10/QP1A.190711.019/eng.zhao.20261106.015454:eng/test-keys
   ```
   fingerprint 里 `eng.<用户名>.<编译时间>` 就是自己编的铁证；`ro.build.type` = `eng`。

6. **stop/start 实测**：`adb -e shell stop && adb -e shell start` 约 30 秒恢复（等 `sys.boot_completed=1`）。改 framework 代码（ch03 起）后的标准刷新手段，比重启模拟器快一个数量级。
